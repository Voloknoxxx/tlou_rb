# The Last of Us — механики для Roblox Studio

Полный набор механик в стиле The Last of Us: тяжёлое «весомое» передвижение,
стрельба от третьего лица через плечо, **собственная процедурная анимация
R6-скелета**, оружие ближнего/дальнего боя, метательное и процедурные модели
оружия.

Всё написано **без внешних ассетов** — ни одного Asset ID. Оружие, руки,
эффекты и интерфейс строятся кодом, поэтому пакет работает в любом месте
сразу после открытия.

---

## Как запустить (2 способа)

### Способ 1 — просто открыть готовый файл (самый быстрый)

1. Скачай `TLoUMechanics.rbxlx` из этого репозитория.
2. Открой его в **Roblox Studio**: `File → Open from File…`.
3. Нажми **Play** (F5).

Всё уже подключено: скрипты лежат по своим местам, а на карте есть
тестовый полигон — разрушенное здание, ящики для залезания, низкие стены
для вольта, балкон с лестницей, машины для укрытий и деревья.

### Способ 2 — через Rojo (для разработки)

```bash
# один раз
aftman install        # или: rojo уже установлен глобально
rojo serve            # затем в Studio: Plugins → Rojo → Connect
```

Исходники в `src/` разложатся по сервисам автоматически
(`default.project.json`). Это удобный режим для правок «на лету».

### Пересобрать файл места после изменений в `src/`

```bash
python3 generate_place.py     # → TLoUMechanics.rbxlx
```

## Что реализовано

### Движение (MovementController + MovementService)
- **Тяжёлая ходьба** — базовая скорость 14 studs/s, TLoU про вес, а не про скорость.
- **Бег как рывок**, а не режим перемещения: тратит выносливость, восстанавливается с задержкой.
- **Приседание** (медленно, тихо) и **лежание ничком** (почти бесшумно, но нельзя стрелять).
- **Вольт/залезание**: луч вперёд ищет уступ высотой 2.5–7 studs, затем игрок проигрывает дугу поверх препятствия вместо стандартного мантла Roblox.
- **Наклон (lean/peek)** из-за укрытия со смещением камеры.
- **Выносливость** предсказывается на клиенте и примиряется сервером.
- **R6-риг**: место генерируется как R6, а сервер (`RigService`) принудительно
  приводит любого игрока к R6 — даже если тот зашёл с R15-аватаром. Стандартный
  `Animate` отключается, чтобы не спорить с нашим аниматором.

### Камера (CameraController)
- Настоящее **третье лицо через плечо**: камера вращается вокруг персонажа,
  смещена к правому плечу. Мышь вращает камеру напрямую.
- **Корпус поворачивается за камерой** с небольшой задержкой — поворот
  ощущается весомым, а не мгновенным. Именно эта задержка даёт аниматору
  реальную скорость поворота, по которой включается переступание на месте.
- Прицеливание подтягивает камеру к плечу и сужает FOV (76 → 50), бег
  расширяет FOV (84).
- **Покачивание при ходьбе** и **инерция/свей** от движения мыши.
- **Отдача — пружина**: камеру подбрасывает и она возвращается.
- **Тряска камеры** от выстрелов и взрывов.
- Коллизия камеры со стенами: камера не заходит в геометрию.

### Анимация (AnimationSystem + R6Rig + AnimatorController)
Вся анимация **процедурная** — ни одного Asset ID, ни одной загруженной
анимации. Поза считается кодом каждый кадр и пишется в `Transform` сустава.

> **Тип сустава.** С `Avatar Joint Upgrade` (Phase 2, включён по умолчанию)
> движок заменяет `Motor6D` в заспавненном персонаже на
> `AnimationConstraint`. Проверка `IsA("Motor6D")` такие суставы **не**
> находит, поэтому поиск суставов возвращает пусто и поза молча не
> применяется — механики работают, а анимаций нет. Код ходит через
> `R6Rig.isJoint`/`collectJoints` и понимает оба класса (у обоих есть
> `Transform`), а место дополнительно отключает сам апгрейд
> (`StarterPlayer.AvatarJointUpgrade = Disabled`).
>
> **Тайминг.** `Motor6D.Transform` — это значение на один кадр. `Animator`
> перезаписывает его между `PreAnimation` и `Stepped`, а батч, применяющий
> его, выполняется сразу после `Stepped`. Поэтому аниматор пишет позу в
> `RunService.PreSimulation`; запись в `Heartbeat` (это `PostSimulation`)
> попадает **после** батча и отбрасывается до применения — персонаж остаётся
> в позе покоя, без единой ошибки в выводе. Стандартный скрипт `Animate`
> гасится и на сервере, и на клиенте: это `LocalScript`, он может успеть
> запуститься раньше, чем реплицируется его удаление, а оставшиеся
> `AnimationTrack` держат `Animator` занятым.

- **Ходьба и бег**: цикл шага привязан к пройденному расстоянию, а не ко
  времени, поэтому ноги не «скользят» на любой скорости.
- **Переступание на месте (turn-in-place)**: когда корпус доворачивается, не
  двигаясь, персонаж переступает ногами. Это ключевая механика TLoU —
  поворот тела читается по шагам, а не по скольжению.
- **Присед и лежание**: сгиб ног, наклон корпуса и опускание силуэта — поза
  даёт визуальное снижение, физика (HipHeight = 0) остаётся честной.
- **Стойка с оружием**: руки держат оружие у бедра (low ready), при
  прицеливании поднимаются к глазу.
- **Покачивание корпуса**, **дыхание в покое**, **стабилизация головы**
  против наклона корпуса.
- Поза применяется **на всех клиентах ко всем персонажам**: `Motor6D.Transform`
  не репликуется, поэтому каждый клиент считает одинаковую позу сам. Стойки
  передаются атрибутами персонажа, которые репликуются автоматически.

### Стрельба и оружие (WeaponController + CombatService)
- Режимы огня: **Auto / Semi / Bolt / Pump / Swing / Throw**.
- **ADS**: узкий разброс, отдельная поза оружия.
- **Перезарядка** по патрону (для дробовика — по одному патрону) и общий магазин.
- **Дробовик** с несколькими дробинками, **лук** (бесшумный, 1 стрела), **снайперская винтовка** с болтовым затвором.
- **Ближний бой** конусом: мачете, бита.
- **Метательное**: коктейль Молотова, дымовая шашка, кирпич — с областью урона и дымом.
- **Зональный урон**: голова ×2.5, конечности ×0.75.
- **Даунed-состояние**: вместо мгновенной смерти игрок падает и может истечь кровью; есть таймер и аптечка.
- **Авторитетная проверка выстрела** на сервере: пошаговый рейкаст отсекает стрельбу сквозь углы.

### Визуал (EffectsController + WeaponModels + WeaponVisualController)
- **Процедурные модели оружия** из обычных Part: ствол, магазин, приклад, прицел, глушитель, затвор, рукоять, мушка — у каждого оружия свой силуэт.
- **Оружие в руке персонажа**, а не на камере: модель приваривается к правой руке и движется вместе с ней. Поэтому своё оружие видно в мире так же, как его видят другие, и нет геометрии, привязанной к камере, которая протыкает стены.
- **WeaponVisualController** показывает оружие **других игроков** в их руках (в третьем лице это обязательно): сервер пишет, что у кого в руках, в атрибут персонажа.
- **Трассеры**, **вспышки выстрела**, **вылет гильз**, **попадания** (пыль, искры, отверстия по материалу поверхности), **кровь** при попадании в персонажа, **взрывы** и **дым**.
- **HUD**: дуга здоровья с виньеткой при низком HP, полоса выносливости, патроны «магазин / запас», слоты оружия, компас, хитмаркер, индикатор шума, оверлей «DOWNED».

### Stealth-основа
- Каждое действие издаёт **шум** (ходьба 8, бег 26, спринт 40, присед 2, лёжа 0, выстрел 120, глушёный 18). Сервер рассылает шумовые пинги — на них можно навесить ИИ.

## Архитектура

```
src/
  shared/                 → ReplicatedStorage.TLoU.Shared
    Config.lua            все настройки «ощущения» (скорости, FOV, урон, шум, анимация, риг)
    Weapons.lua           таблица данных оружия (добавить оружие = добавить данные)
    WeaponModels.lua      процедурный билдер моделей оружия
    AnimationSystem.lua   чистая математика поз (шаг, переступание, стойки)
    R6Rig.lua             R6-скелет, применение позы, конвертация R15 → R6
    Net.lua               обёртка над RemoteEvent'ами
    Util.lua              хелперы (зоны попадания, интерполяция, deep copy)

  server/                 → ServerScriptService.TLoU.Server
    Bootstrap.server.lua  запуск сервисов, отключение лишних контролов Roblox
    Modules/
      CombatService.lua   авторитетная стрельба, урон, перезарядка, метание, даунed
      MovementService.lua стойки, выносливость, шум, применение к Humanoid
      RigService.lua      принудительный R6, отключение стандартного Animate
      InventoryService.lua слоты и лоадаут

  client/                 → StarterPlayerScripts.TLoU.Client
    Bootstrap.client.lua  порядок запуска контроллеров
    Controllers/
      State.lua           единое состояние + сигналы
      Signal.lua          мини-эмиттер событий
      NetworkController.lua перевод серверных событий в состояние
      MovementController.lua ходьба/бег/присед/лежанка/вольт/наклон
      AnimatorController.lua процедурная анимация всех персонажей (R6)
      CameraController.lua камера через плечо, поворот корпуса, свей, отдача
      WeaponController.lua оружие в руке, огонь, ADS, перезарядка, смена, ближний бой
      WeaponVisualController.lua оружие в руках других игроков
      EffectsController.lua трассеры, вспышки, гильзы, попадания, кровь, взрывы
      HUDController.lua   весь интерфейс, собранный кодом
```

**Ключевой принцип:** клиент отвечает за «ощущение» (мгновенная отдача,
трассер, анимация), сервер — за истину (патроны, урон, попадания, стойка).
Контроллеры не зависят друг от друга напрямую — они общаются через `State`
и сигналы, поэтому любой из них можно заменить отдельно.

## Как добавить новое оружие

Достаточно одной записи в `src/shared/Weapons.lua`:

```lua
Weapons.SilencedRifle = gun({
    id = "SilencedRifle",
    name = "Silenced Rifle",
    category = "Firearm",
    model = "Rifle",              -- форма из WeaponModels
    damage = 40, fireMode = "Semi", rpm = 220,
    magazine = 20, reserveMax = 100, reloadTime = 2.0,
    bulletSpread = 1.8, aimSpread = 0.3, recoil = 1.6,
    range = 320, pellets = 1, silenced = true,
    adsTime = 0.22, raiseTime = 0.5,
    visual = {
        bodyColor = Color3.fromRGB(30,30,32),
        accentColor = Color3.fromRGB(60,60,62),
        length = 2.6, stock = true,
        scope = "small", suppressor = true, woodFurniture = false,
    },
})
```

Затем добавь `id` в `Weapons.defaultLoadout()`. Модель, иконка в HUD,
патроны и звук соберутся автоматически.

## Тесты

```bash
python3 run_tests.py
```

Прогоняет 768 проверок на Luau CLI: инварианты данных оружия (обязательные
поля, режимы огня, разброс при прицеливании ≤ разброс от бедра, дробовик
имеет несколько дробинок), логику `Util`, работу `Signal` и — главное —
сборку **каждой** процедурной модели оружия (наличие Handle, Muzzle,
сварка всех частей, отсутствие коллизий).

Требуется бинарь Luau. Скрипт берёт его из `/tmp/luaubin/luau`
(переопределяется переменной `LUAU_BIN`).

## Заметки по настройке «ощущения»

Почти всё вынесено в `src/shared/Config.lua`:

- хочешь быстрее — подними `Movement.WalkSpeed` / `SprintSpeed`;
- хочешь «ещё тяжелее» — опусти скорости и `Camera.FOVLerp`, подними `BobAmplitude`;
- хочешь сильнее отдачу — `Camera.RecoilKick`, `Camera.RecoilRecovery`, поле `recoil` у оружия;
- хочешь жёстче stealth — увеличь разницу `Combat.Noise` между стойками.

## Известные ограничения

- Анимация процедурная, а не загруженная: она не использует `AnimationTrack`
  и поэтому не смешивается со стандартными анимациями Roblox. Если позже
  захочешь добавить motion-captured клипы, их можно накладывать поверх —
  `Animator` в риге остаётся нетронутым.
- Нет ИИ врагов: механика шума готова, но слушателей нужно добавить.
- Механики рассчитаны на двух и более игроков; в одиночном Play даунed и
  урон видны, но стрелять не в кого.
